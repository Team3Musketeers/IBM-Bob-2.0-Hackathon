# Ghostwriter — Communication Debt Score Specification

## Purpose

The Communication Debt Score measures the gap between what a pull request
communicates and what the code actually changes.

The score ranges from 0 to 100.

A higher score means the pull request contains more communication debt.

This score evaluates communication quality, not code quality.

---

## Score Formula

Communication Debt Score =

description_gap
+ scope_creep
+ unanswered_risk

Maximum:

40 + 30 + 30 = 100

---

# 1. Description Gap — 0 to 40

This component measures how much important behavior discovered by the
Technical Truth-Teller was missing from the original PR description.

## 0 points

The PR description accurately explains the important changes.

## 1–10 points — Minor gap

Examples:

- small implementation details
- minor CSS behavior
- naming changes
- comments
- internal refactor details

## 11–25 points — Meaningful gap

Examples:

- undocumented behavior changes
- lifecycle changes
- validation logic changes
- functional changes across additional files

## 26–40 points — Major gap

Examples:

- breaking behavior
- API changes
- dependency changes
- significant user-visible behavior
- security-sensitive changes

---

# 2. Scope Creep — 0 to 30

This component measures work that differs from what the linked ticket requested.

Ghostwriter must distinguish between benign and concerning undisclosed scope.

## Benign undisclosed scope

Examples:

- tests
- comments
- documentation
- formatting
- defensive implementation details directly supporting the requested fix

These should receive little or no penalty.

Suggested range:

0–5 points

## Concerning undisclosed scope

Examples:

- unrelated behavior changes
- dependency changes
- API changes
- compatibility changes
- new product functionality
- changes unrelated to the ticket outcome

Suggested range:

6–30 points

## Incomplete scope

If the ticket explicitly requests something that the PR does not implement,
this should also increase the scope score.

The score should depend on the importance of the missing requirement.

---

# 3. Unanswered Risk — 0 to 30

This component measures the importance of the questions generated by
Reviewer's Ghost.

Questions must not be scored only by quantity.

The synthesis should consider:

- severity
- evidence quality
- confidence
- possible user impact

## Low risk

0–8 points

## Medium risk

9–18 points

## High risk

19–30 points

---

# Confidence Handling

Findings may have:

- high confidence
- medium confidence
- low confidence

Suggested confidence multipliers:

high confidence = 1.0

medium confidence = 0.7

low confidence = 0.4

---

# Important Synthesis Rule

The synthesis step must NOT discover new problems.

It may only score findings already produced by:

1. Technical Truth-Teller
2. Scope Auditor
3. Reviewer's Ghost

---

# Example: PR #69571

The Scope Auditor detected an additional test file that was not mentioned in
the ticket or PR description.

Adding tests is directly related to the requested work and is generally
beneficial.

Classification:

benign undisclosed scope

Therefore this should receive little or no scope-creep penalty.

---

# Score Classification

| Score | Communication Debt |
|---|---|
| 0–20 | Low |
| 21–40 | Moderate |
| 41–60 | Significant |
| 61–80 | High |
| 81–100 | Critical |

This classification evaluates PR communication quality, not code quality.
